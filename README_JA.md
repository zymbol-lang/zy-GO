# 囲碁

> **対象は Zymbol v0.0.8**

端末で遊ぶ囲碁。すべて Zymbol で書いてある。AI の相手、規則の完全な適用、
そして自動の目算を備える。

囲碁 は Zymbol で書かれた三つめの本格的な端末遊戯である。先に
[Serpiente](https://github.com/zymbol-lang/zySerpiente) と
[Hov veS](https://github.com/zymbol-lang/zyKlingonGalaxy) があった。これが確かめ
ようとしたのは、それらとは別の種類の言語の力である。すなわち、協調する複数の
module を渡り歩く大きな持続的データ構造（最大 361 点）、再帰による図の探索
（塗り潰しによる連とダメの判別）、発見的な判断の機関、そして一升がちょうど端末の
二桁を占める広い字形の盤面である。

> **Zymbol v0.0.8 の検証事業** — 深い再帰の塗り潰し、隔離された関数の視野を
> またぐ複数 module の状態の受け渡し、`>>~` の下での広い字形の配置、`>>?` に
> よる端末の大きさの関所、そして五つの言語にわたる二段の多言語化（実行時の
> 表示文字列と、識別子そのものの翻訳）に負荷をかける。

> **English:** [README.md](README.md) · **Español:** [README_ES.md](README_ES.md)
> · **i18n の点検:** [AUDITORIA_I18N_ES.md](AUDITORIA_I18N_ES.md)
> · **設計書:** [DESIGN.md](DESIGN.md) · **複雑さの試験:** [BENCHMARK.md](BENCHMARK.md)

## なぜ日本語か

碁は中国で生まれ（围棋、*wéiqí*）、韓国（바둑、*baduk*）でもベトナム（cờ vây）でも
打たれている。西洋へは日本を通って伝わった。だから国際的な呼び名が *go* であり、
世界で使われる語彙 — *komi*、*atari*、*ko*、*hoshi*、*dame*、*jigo* — が日本語なので
ある。

そこで、この program は日本語で書いてある。識別子も module の名も file の名も、
漢字と仮名を使う。原文の中の規則の語彙は、打ち手がすでに知っている語彙と同じで
ある。これは Zymbol 事業の穴を埋めることでもある。韓国語（Z-Tic-Tac-Toe）、
クリンゴン語（Hov veS）、スペイン語とギリシャ語（i18n の試験一式）はすでに
あった。日本語だけが無かった。

一方、表示は **五つの言語**で使える。日本語・한국어・中文・English・Español —
アジアで実際に碁が打たれている三つの言語に、この事業を記した二つの言語を足した
ものである。六つめを足すのは三箇所の編集で済む（ベトナム語の *cờ vây* が明らかな
空席である）。言語の file を書き、取り込み、四つの振り分けにそれぞれ一つ枝を足す。

## 遊び方

[Zymbol の通訳系](https://github.com/zymbol-lang/interpreter) v0.0.8 以降が要る。

```bash
git clone https://github.com/zymbol-lang/zy-GO
cd zy-GO
zymbol run 囲碁.zy
```

> 木を歩く実行系（既定）で動かす。register VM（`--vm`）の module の支えは
> 部分的である。[限界](#限界)を見よ。

### 端末の大きさ

対局は起動時に `>>?` で本当の端末の大きさを読み、収まる盤だけを差し出す。盤の
一升はちょうど**二桁**なので、盤の塊は `2N + 7` 桁 × `N + 2` 行を占める。

| 盤 | 日本語 | 最小の端末 | 脇に区画を置く場合 |
|-----|--------|-----------|------------------|
| 9 × 9 | 九路盤 | 27 × 15 | 51 × 13 |
| 13 × 13 | 十三路盤 | 35 × 19 | 59 × 17 |
| 19 × 19 | 十九路盤 | 47 × 25 | 71 × 23 |

横並びの配置は桁を多く要る代わりに行が少なくて済む。だから 19 × 19 の盤は、
区画を脇に置いたまま古典的な 80 × 24 の端末に収まる。

脇に区画を置く幅に足りなければ、状態の区画は盤の脇ではなく下に描かれる。最小に
すら足りなければ、その大きさの盤は設定の画面で必要な寸法とともに灰色に落とされる。
9 × 9 にも足りない端末では、崩れた盤を描くのではなく文言を出して終わる。

### 対局設定

一つの画面がすべての選択を抱える。`↑` `↓` で行を選び、`←` `→` で値を変え、
`↵` で対局が始まる。

```
     ╭──────────────────────────────────────╮
     │                 囲碁                 │
     │            Zymbol v0.0.8             │
     ├──────────────────────────────────────┤
     │ ► 路盤        ‹    九路盤    ›       │
     │   コミ        ‹     6.5      ›       │
     │   主題        ‹      石      ›       │
     │   言語        ‹    日本語    ›       │
     ├──────────────────────────────────────┤
     │      ↑↓ 選択   ←→ 変更   ↵ 開始      │
     ╰──────────────────────────────────────╯
```

いまの端末に収まらない盤の大きさは、必要な寸法とともに薄く示される。コミを整数
（6 か 7）にすると 持碁 — 引き分け — が起こりうる。既定の 6.5 では起こりえない。

パスが二つ続けば対局は終わり、目算がひとりでに走る。

```
     ╭──────────────────────╮
     │         終局         │
     ├──────────────────────┤
     │           ⚫    ⚪   │
     │ 石        2     0    │
     │ 地        79    0    │
     │ コミ      —     6.5  │

     │ 合計      81    6.5  │
     ├──────────────────────┤
     │    黒の74目半勝ち    │

投了は 中押し勝ち として告げる（目算はしない）。ぴたりと並べば 持碁 と告げる。

## 主題

三つの石の組。対局の途中でも `t` で切り替えられる。三つとも一升はちょうど二桁の
ままなので、配置がずれることは決してない。

| 主題 | 黒 | 白 | 幅 | 覚書 |
|------|-----|-----|-----|------|
| 石 | ⚫ | ⚪ | 二桁 | 既定。絵文字の組の中では端末の支えが最も厚い。 |
| 月 | 🌑 | 🌕 | 二桁 | 寸法は同じ、趣が違う。 |
| 字 | `X` | `O` | 一桁 + 継ぎ | 絵文字の幅を測り違える端末のための持ち運べる逃げ道。 |

字の主題は `●` と `○` をあえて避けている。あれらは *East Asian Ambiguous* の
幅を持ち、西洋向けの端末では一桁、CJK 向けに設定された端末では二桁になる。桁の
算術を壊すのはまさにその類の字形である。

## 実装した規則

| 規則 | 日本語 | 振る舞い |
|------|--------|---------|
| 石と連 | 石 · 連 | 直交して隣り合う同じ色の石が一つの連をなす |
| ダメ | ダメ | 連に隣り合う空点 |
| 取り | 取り · アゲハマ | ダメが零になった連は取り除かれ、アゲハマとして数えられる |
| 取りの優先 | — | 打った石自身のダメを調べる前に、相手の連を取る |
| 自殺手 | 自殺手 | 先に取りが成立しないかぎり打てない |
| コウ | コウ | 直前の局面をそのまま再現する手は打てない |
| パス | パス | 常に打てる |
| 終局 | 終局 | パスが二つ続いたとき。program が決めることは決してない |
| 投了 | 投了 | 対局中の `q` |
| コミ | コミ | 設定できる。白に足される償い |
| 持碁 | 持碁 | コミが整数のときだけ起こりうる |
| 星 | 星 | 盤の大きさごとに描く。定石にも使う |

位置による超コウ（直前だけでなく、盤面全体の*どの*繰り返しも禁じる）は選べる
仕組みとして用意してある。局面の履歴を抱える費用がかかるので、既定では切ってある。

### やめどきを知る

碁に自動の終局は無い。対局は**両者がパスしたとき**に終わる。打つ価値のあるものが
もう残っていないと判じられるのは打ち手だけであり、そして初級者にはまだその判断が
できないからである。だから program はそれを決めない。しかし、手番の側に、非合法
でも自分の眼を埋めるのでもない手がもう無いことは告げる。

```
 打つべき所がない — パスを
```

それが局面を読む `核/思考.zy` である。`眼()` は空点がある色の眼かどうかを決め、
`有用手()` はそうでない合法手を並べる。AI が建つのもこの同じ二つの関数の上である。
自分の眼を埋めるエンジンは相手ではない。自滅の機械である。

## 計算

囲碁 は**地と石の両方を数える**中国式で目算し、それを日本語の語彙で示す。一方の
点数は盤上の自分の石に、自分の石が完全に囲んだ空点を足したもの。白はそこにコミを
加える。

中国式を選んだのには決め手が一つある。program だけで計算しきれることである。
日本式の地の計算は、どの群が死んでいるかを両者がまず*合意する*ことを要る。その
交渉の段は初級の力の AI には正直に片づけられず、間違えれば勝者を取り違えて告げる
ことになる。中国式は「セキ」も特別扱いなしで正しく収める。共有のダメは誰の地にも
ならないからである。

同じ最終局面に対して、二つの方法はほとんどいつも一目以内で一致する。だから
目にする結果は、日本式で数えたときの結果でもある。

## 思考

相手は探索の機関ではなく、層をなす発見的な着手の生成器である。合法な候補一つ
ごとに下の層を渡って点数を積み、最も高いものを打つ。そこに級に応じた量の
無作為さが混じる。

| 層 | 日本語 | 何を評価するか |
|----|--------|--------------|
| 1 | 合法手 | 合法性。自殺せず、コウを侵さず、自分の眼を決して埋めない |
| 2 | 取り | 取ること。取れる石の数で重みをつける |
| 3 | アタリ逃げ | アタリからの逃げ。ただし逃げて本当にダメが増えるときだけ |
| 4 | アタリ | 相手の連をアタリにすること |
| 5 | 形 | 相手の最終手のまわりの三路四方の型（ハネ・伸び・接続・切り） |
| 6 | 勢力 | 勢力の図。二つの勢力圏の境目を好む |
| 7 | 布石 | 序盤の定石。星と小目、盤が広いうちは一線二線を避ける |

| 級 | 日本語 | 振る舞い |
|----|--------|---------|
| 初級 | 初級 | 第一層から第四層まで。上位の候補の中で大きく揺れる |
| 中級 | 中級 | 全層。ほどよく揺れる |
| 上級 | 上級 | 全層、候補の走査を一路広げ、ほぼ決まりきって打つ |

**正直な棋力の見立て**: 弱い初級者、25 級あたり。ほうっておいた石は取るし、
自分の石はアタリから救うし、自分の眼を埋めることは拒むし、隅から打ち始め、盤が
広いうちは一線二線を避ける。シチョウを最後まで読むことも、死活を判ずることも
しない。それでよい。この AI は、言語が非自明な判断の機関を表せることを示すために
在るのであって、あなたを負かすために在るのではない。

上の表に無く、それでも席に値する項が一つある。**自らアタリに入る手**である。何も
取らずに自分の連をダメ一つで残すことへの罰が無ければ、エンジンは嬉々として取られ
に行き、他のどの層も無駄になる。

級は一つの数である。最善からどれだけ下まで選ばれうるか（60 / 25 / 5 点）。初級と
は、わざと下手に打つ program ではない。良い手とほぼ良い手を見分けられない
program である。

│   ├── 한국어.zy        ko
│   ├── 中文.zy          zh
│   ├── English.zy       en
│   └── Español.zy       es
├── 試験/                試験の一式
│   ├── 全試験.sh        すべてを走らせる
│   ├── 文字試験.zy      桁の算術
│   ├── 言語検証.zy      i18n の完全性の関所
│   ├── api試験.zy       api/ が同じ engine に解けること
│   ├── 盤試験.zy        規則のエンジン
│   ├── 計算試験.zy      目算
│   ├── 性能試験.zy      再帰の深さと 19×19 の費用
│   └── 図.zy            読める試験の局面のための文字の図の読み手
└── api/                 識別子ごとの API の翻訳
    ├── english.zy
    └── espanol.zy
```

入口は四つ、対局は一つ。`囲碁.zy`・`바둑.zy`・`围棋.zy` はあらかじめ選ぶ言語だけが
違う。`go.zy` は言語の品書きから開き、漢字仮名を打ちにくい端末のために在る。

盤は `N × N` 点の**平坦な配列**で、添字は 1 から始まり、値は `0` が空、`1` が黒、
`2` が白である。点 `(行, 列)` は添字 `(行 - 1) × N + 列` に置かれる。ここでは
平坦な配列が行列に勝つ。隣の計算が容易になり、この program で最も熱い塗り潰しの
最奥の輪から入れ子の添字づけを追い出せるからである。

名前で直に呼ばれる Zymbol の関数は**視野が隔離**されており、見えるのは引数だけ
なので、盤が大域の状態になることは無い。盤はどの関数にも明示的に渡され、書き
換えを意図するところでは `<~` の出力引数を通して書き換えられる。module どうしの
約束の全体は [DESIGN.md](DESIGN.md) を見よ。

## 多言語化

囲碁 は Zymbol の i18n の仕組みを**両方**使う。二つは別の問題を解く。

**実行時の表示文字列**（`言語/`）— 打ち手が読む文である、五つの言語で。
`言語::設定(コード)` が ISO 639-1 の符号で言語を選び、`言語::語(鍵)` が文字列を
返す。この選択は module の状態として対局のあいだ保たれるので、描画のどの関数も
言語の引数を持ち歩かなくてよい。

どの言語も同じ四つの関数の約束を満たす。`語(鍵)` は静的な引きであり、残る三つは
文を組み立てる。静的な表では「白の1目半勝ち」を五つの語法で表せないからである。

| 関数 | 役目 |
|------|------|
| `語(鍵)` | 鍵に対する静的な文字列 |
| `路盤名(路)` | 盤の名 — 九路盤 · 9줄 바둑판 · 九路棋盘 · 9×9 |
| `結果文(勝色, 差, 中押)` | 結果の文 — 白の1目半勝ち · 백 1집반승 · 白胜1目半 · White wins by 1.5 points · las blancas ganan por 1,5 puntos |
| `取石文(数)` | 取りの知らせ。言語が要るなら複数形の一致も添えて |

鍵は領域の接頭辞を付けた**日本語の概念**である（`区画.アゲハマ`、`報せ.コウ`）。
この仕組みの土台が日本語であり、他のすべての言語がその上に載るからである。
`区画.アゲハマ` を求めるのは概念を求めているのであって、英語の識別子を求めて
いるのではない。仕組みを検められるものに保つのはこの接頭辞である。鍵が自分自身の
日本語の訳語と同じ形になることはありえない（`終局.石` であって、ただの `石` では
ない）。だから鍵を欠く言語は鍵そのものを返し、`試験/言語検証.zy` は親目録を —
日本語も含めた — すべての言語に突き合わせて歩き、そのまま返ってきた文字列があれば
落ちる。言語を足すのは三箇所の編集で、関所が忘れ物をその場で告げる。

**識別子ごとの API の翻訳**（`api/`）— エンジンの公開 API を英語とスペイン語の名で
差し出す、純粋な再輸出の層である。論理は無く、実行時の費用も零。日本語を読まない
開発者が `en::play(...)` や `es::jugar(...)` に対して自分の前面を書け、
日本語の原文を一度も開かずに済む。これは
[I18N.md](../interpreter/I18N.md) の三層の型を、試験の作り物ではなく本物のエンジン
に当てたものである。

定数は `.` で、関数は `::` で再輸出し、読むときも同じ形になる（`en.BLACK`、
`en::play(…)`）。二つの層は `核/` の公開面をすべて覆う — `盤` から 21、`規則`
から 6、`計算` から 4。再輸出の層は論理を持たないので試すべきは一つだけで、
`試験/api試験.zy` が同じ手を両方の名前で打ち、盤と取数とコウ点を — `着手` の
出力引数も含めて — 突き合わせる。

**道具の言葉**（`言語/道具.zy`）— `棋戦` と `集計` は対局ではない。打ち手の
ために在る目録に五十ほどの計測の名札を混ぜれば目録が薄まるので、道具の言葉は
別の目録に置き、日本語・英語・スペイン語の三つで答える。既定は対局と同じく日本語である。分かれているのは目録だけで、
現在の言語は 言語/取次 の一つきりの状態から読み、関所も同じやり方で歩く。
`棋譜/` の記録は訳さない。二つの言語に割れた資料は二つの資料だからである。

ここで述べた作りは
[USERAPPI18N.md](https://github.com/zymbol-lang/interpreter/blob/main/USERAPPI18N.md)
に共通の指針として書き出してある。囲碁 がまだそれに届いていないところは
[AUDITORIA_I18N_ES.md](AUDITORIA_I18N_ES.md) が記している。

## 限界

1. **死石が生きているものとして数えられる。** 中国式の目算は、死石が実際に取り
   除かれていることを前提とする。死石を盤に残したまま終局すれば、それは持ち主の
   ものとして数えられる。通常の作法どおり、死んだ群が盤から消えるまで打ち続ける
   こと。死んだ群の発見的な判別は今後の課題である。
2. **AI は初級の力しかない。** 上に述べたとおり。シチョウも読まず、死活も解かず、
   ヨセも数えない。
3. **既定では単純なコウだけ。** 位置による超コウは選んで入れる。
4. **絵文字の幅は端末と字体に左右される。** 石が升からはみ出すなら、`t` で 字 の
   主題に切り替えること。
5. **いまは両方のエンジンで動く。** この事業が木を歩く実行系だけで出発したのは、
   `--vm` が module の関数の出力引数を黙って落とし（HLZ-008）、その中で String を
   切れなかった（HLZ-009）からである。どちらも通訳系の側で直り、六つの試験一式は
   — 対局そのものも — `zymbol run` と `zymbol run --vm` で等しく走る。

## 言語についての発見

囲碁 を組む途中で見つけた不具合・欠け・思いつきは
[HALLAZGOS_ES.md](HALLAZGOS_ES.md)（スペイン語）に記してある。Serpiente と
Hov veS の慣わしに倣ったものである。

| ID | 種類 | 説明 | 状態 |
|----|------|------|------|
| HLZ-001 | 欠け | module の中の `CONST := -1` が E013 になる — 符号付きの literal は式として読まれる | API をそれに合わせて設計し直した |
| HLZ-002 | 不具合 | 関数の引数から算出した配列の添字が「Int のはずが Float」で解析に落ちる | 逃げ道: 一箇所の `##!` 変換 |
| HLZ-003 | 不具合 | `##.0 == 0` が `#0` なのに `##.0 >= 0` と `##.0 <= 0` はどちらも `#1` | 未 |
| HLZ-004 | 不具合 (LSP) | 下位 folder の module についての点の慣わしが、通訳系では動くのに language server では E001 と咎められる | 未 |
| HLZ-005 | 欠け | `<# ./../x` が読めない。`<# ../x` が要るのに、誤りの文がそれを言わない | 文書化した |
| IDEA-001 | 思いつき | 表示幅を測る基本命令が無く、`0d\|c\|` の文字列の解析だけが Char→Int の道である | 提案 |

**九つのうち七つが通訳系の側で直った。**それぞれに退行の試験が付き、対の一式が
両方のエンジンで走らせるので、気づかれずにまた分かれることはない。v0.0.8 の
通訳系の CHANGELOG を見よ。

尖っているのは HLZ-003 である。二つの値は同じように印字されるので、落ちた確認が
`expected 0, got 0` と読める。碁の点数はコミのせいで半整数になり、あらゆる点数が
その境目の Float 側に置かれる。

Serpiente を [BUG-004](https://github.com/zymbol-lang/zySerpiente) で噛んだ二桁の
問題 — 一つの座標に収めた二桁の絵文字 — には、ここでは特別扱いではなく構造で
答えている。**どの主題でも盤の一升は二桁**なので、石は升をちょうど埋め、盤面の
算術に継ぎ目が無い。`試験/文字試験.zy` はそれを直に確かめ、盤の一行が三つの主題で
同じ寸法になることを検める。
